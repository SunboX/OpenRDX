# OpenRDX v1.08

OpenRDX 1.08 improves drive and cartridge status reporting.

- Reports the drive manufacturing date and reads cam and power-source states
  from the device.
- Displays stored cartridge load, read, and write counters when valid metadata
  is available. Missing counters remain unavailable.
- Reports cartridge temperature and write protection without zero-value
  placeholders for unavailable sensor readings.
- Identifies the firmware as version 1.08 and supports discovery by the updater.

Stored usage counters are read when a cartridge is admitted; this release does
not update them with session activity. See the
[status protocol reference](https://github.com/SunboX/OpenRDX/blob/v1.08/docs/reference/rdx-manager-protocol.md#drive-and-cartridge-status)
for field details and limitations.

## Download and install

Download [OpenRDX-v1-08.zip](https://github.com/SunboX/OpenRDX/releases/download/v1.08/OpenRDX-v1-08.zip)
and extract it into its own directory. Keep `OpenRDX-v1-08.bin` and its matching
`OpenRDX-v1-08.json` manifest together with the other installation files. Verify
the included checksums before installation.

Follow the [installation guide](https://github.com/SunboX/OpenRDX/blob/v1.08/docs/getting-started/installation.md)
for your receiver and keep the [receiver recovery guide](https://github.com/SunboX/OpenRDX/blob/v1.08/docs/development/rom-loader-recovery.md)
available. Installation requires an empty bay, stable power, and exact device
selection. The guarded Windows updater and the advanced FlashBurner route have
different artifact requirements; follow the guide for the selected route.

## Supported hardware and limitations

This release targets the Tandberg Data RDX QuikStor external USB 3.0 receiver
built around TI TUSB9261. It supports RDX cartridges and qualifying, unlocked
standard SATA drives.

OpenRDX remains experimental. Local testing has been reported successful;
broader drive compatibility, repeated cold starts, and long-running I/O still
need further testing. See the [firmware behavior and validation limits](https://github.com/SunboX/OpenRDX/blob/v1.08/docs/reference/firmware-behavior.md#validation-boundary).
